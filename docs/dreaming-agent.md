# 目录 Dreaming Agent

第一版 scope 为 `directory`，持久化 `policyVersion` 用于后续扩展与兼容检查。任务调度、认领/租约、证据读取、目录写入与 DSH 会话宿主分开：Core 管理原子提交与断点，Runtime 协调运行，DSH 提供真实 Agent 和会话；UI 只请求状态与控制动作。

新会话头部传入目录所属工作区的 `cwd`，优先从匹配 namespace 的活动普通会话取值，再从持久化会话头部恢复；不读取历史正文。项目/会话作用域找不到真实路径时暂停并提示先打开对应普通会话，不以插件目录冒充工作区。全局/自定义导入空间无唯一工作区时使用宿主运行目录作为查看地址，工具权限仍按 run scope 隔离。打开会话前完成宿主 flush。旧版本生成的无 `cwd` 会话头不可改写；打开或继续时提示终止旧轮并重新开始，保留已提交的目录修改与旧日志。

## 工具与权限

| 工具 | 行为 |
| --- | --- |
| `memory_list_topics` / `memory_expand_topic` | 运行空间内目录导航与分页总览，独立 scoped 实现 |
| `dreaming_search` | 冻结有效 Event、其引用的原始消息及有效图谱检索 |
| `dreaming_read` | 完整 Event、来源 Block、图谱节点的只读分页 |
| `dreaming_directory` | 当前章节改名、小节改名/合并、当前批 Event 移动、带来源的总览/经验替换、追加或跨小节原子整理 |
| `dreaming_finish` | 确认当前批已检查；推进下一批，最终结束 |

Agent 只注册上述工具，拒绝继承的 shell、网络、文件和记忆写入工具。普通聊天工具的证据评估批次与使用反馈不复用。`dreaming_search` 使用底层检索；`dreaming_read` 使用 `renderBlock`，不调用会提升层级/改变衰减锚点的 `expandBlock`。Dreaming 系统提示词注入持久用户画像，仅作为相关偏好和长期要求的参考，不能替代目录来源证据；会话不重新摄入记忆，也不继承普通聊天的自动检索上下文。

### 概要整理操作

`set-overview {title,entries}` 只替换指定小节的全部概要，不替换整章。`append-overview` 仅用于真正新增的事实。`move-events` 只改变当前批 Event 的小节归属，不自动移动概要正文。

`rewrite-overview {titles,entries}` 原子替换所列多个已有小节的全部概要；每个 entry 必须显式指定这些小节之一作为 `title`。它支持把事实从错放的小节移到正确小节，也支持合并重复段落、更正旧表述。必须包含所列小节所有需要保留的独有内容，包括目标小节原有概要；未列出的小节保持原样。目标小节可由同一次提交前面的 `move-events` 创建。只有重排概要时也可单独调用，不要求改变 Event 归属。

例如把“旧分类”中的一段移到“新分类”，提交 `titles:["旧分类","新分类"]`，在 entries 中列出两节应保留的全部内容，把该段的 title 改为“新分类”，保留其正文和来源。移动后无需在“旧分类”留下重复正文或仅为通过校验而添加交叉索引。

替换前必须完整读取原有引用来源。Core 按所选小节新概要的来源并集检查，禁止丢失任何原有来源引用；不再要求同一个引用必须留在原小节。任一操作失败则整次提交回滚，其他步骤的改名、移动和重写也不保存。章节版本、认领和冻结来源校验保持有效。

新证据修正旧说法时，优先改写或合并旧段落，同时引用新旧来源并保留时间顺序、适用范围、仍有效的细节和不确定性；不让旧结论继续充当当前事实，再在末尾不断追加补丁。仅因材料较新不能自行裁定矛盾。单小节用 `set-overview`，跨小节用 `rewrite-overview`。这些规则在原生 Agent 与兼容的 detached 路径共用。

概要错误会附上具体 Event ID 和原因：`overview-source-not-retrieved` 表示需要完整读取，按 `nextOffset` 连续翻页；`overview-source-not-in-chapter` 表示来源属于别章，反复读取不会获得本章引用权限；`overview-source-unavailable` 表示未知、已变化或不在本轮冻结范围；`overview-source-reference-missing` 表示替换遗漏旧引用。未知小节、缺少条目 title、空来源和无效正文也分别报错。

## 持久化与并发

任务保存在既有 Topic 状态中，无新增数据库/schema 迁移。任务冻结来源版本，按章节拆成有限上下文页面。提交在 Core 现有事务内检查 run ID、owner、epoch、租约、章节版本、来源有效性和已读证据。大 Event 只有连续分页读完才进入证据集合；检查覆盖断点不依赖最近工具日志的长度。

Event 分页按递归稳定字段顺序序列化，页结果和持久断点绑定完整内容摘要。重启不依赖对象属性插入顺序；旧格式断点或内容摘要改变时清除旧覆盖并从零读取。当前批所有 Event 的完整证据覆盖满足后才能完成，未读完的大 Event 不会被报告为已检查。

暂停等当前步骤到达安全边界，继续时换 epoch；终止立即取消当前请求并提升 epoch，使迟到结果无法写入。已完成写入保留。运行定期续租；崩溃后过期认领可人工继续。并发投影改变来源或章节会拒绝写入，由用户终止后重新规划。

最后一批完成后，Agent 可继续生成最终总结。此时同一 run、owner、epoch 的在途心跳只返回已完成状态，不更新时戳、不重建租约，也不取消总结；Runtime 收到完成状态后停止心跳。其他 owner、旧 epoch 和旧 run 仍被拒绝，已完成轮次仍不能写目录。

用户手动触发的 Dreaming 优先于同一记忆空间的自动目录投影。开始时立即持久化目录占用，阻止任何连接认领新的目录投影；已经认领且租约有效的投影先收尾，界面显示“等待当前后台目录整理完成”，等待期间不请求 Dreaming 模型。收尾完成、失败或租约过期后，再按最新目录冻结批次与来源，过期投影的迟到结果不能覆盖 Dreaming。其他记忆空间的目录任务照常调度。

首次目录尚未生成时，只要有有效投影正在执行，同样可以启动等待；投影收尾后重新规划。没有章节且没有有效在途投影时拒绝启动。在途投影失败或过期后若仍无章节，本轮以“暂无可整理的目录章节”完成并释放占用。等待轮询只读取最新状态；现有每 20 秒心跳续租，不按每次轮询写库。暂停、失效认领和投影结束时仍经过原事务处理状态变化。

暂停和宿主重启后保留目录占用，避免继续时目录已经被后台改写；整轮完成或用户终止后释放占用并唤醒后台任务。暂停轮次的状态会提示用户：后台目录整理等待本轮继续或终止。若其他写入仍改变冻结章节或来源，则立即暂停并标记需要重新开始；旧版本遗留的冲突轮次在继续前同样校验，不再让模型反复重读。界面隐藏该轮次的“继续”，提示终止后重新开始，已提交的修改保留。

小节身份不依赖当前标题；合并保留旧身份的别名，后续普通投影保留身份、别名和有效经验。空改动和回到近期旧状态的编辑被拒绝，不能用反复改名制造进展。

## 增长、结束与消耗

批次最多 24 个 Event，并按预计上下文容量进一步拆小；这是页面大小，不是整轮调用限额。目录页的进度按这些批次计算（例如 `1/14` 批约为 7%），不是简单按章节数计算；一个较大的章节可能拆成多个批次。Dreaming 使用原生 DSH Agent 会话，启动、恢复和切批时追加当前任务；同批后续步骤沿用对话和工具结果，不逐步替换历史，也不重复注入完整任务。相关旧总览完整提供，不设置插件自己的 4000/6000 Token 截断；历史保留和摘要压缩由宿主根据实际模型窗口管理。

流程为检查本批 Event、对照旧总览、只提交有价值的目录调整、完成本批并继续。已有覆盖时允许不修改就完成，不把同一事实的改写当成新内容追加。目录 sections/overview 页绑定内容摘要并持久记录覆盖；任务提供恢复时的已读范围，随后分页按工具返回的 nextOffset 前进。对话中的核对结论、用户方向、错误和成功结果交由宿主保留或摘要。失败写入提案另有持久化记录，不受最近 12 条诊断日志的窗口影响；恢复时提供完整提案，读取错误不再包装为失败写入。

`dreaming_finish` 表示批次已全部检查，允许无需修改；所有冻结批次完成后进入 completed。重复无效工具调用、连续无工具进展的模型步骤或失败时暂停。没有累计 token 限额，界面和控制接口不提供上限设置。内部计量保留实际模型输入结构的 token 估算和输出估算/供应商输出计数，仅用于诊断；目录页和模型任务上下文不展示消耗数字，不声称价格或账单精度。旧任务继续时在原子事务中清除历史 tokenLimit，保留任务、批次进度、证据断点与会话身份。

无进展计数在新增完整 Event 证据、推进连续有效来源页、读取经校验的目录新项或成功修改目录时重置。搜索关键词变化、空结果与重读已覆盖页均不重置；连续 12 次无进展工具调用后暂停，允许其间进行有限探索；一旦有上述有效进展，连续计数从零开始。空响应（含 `(empty)`）或普通文字回复结束但任务未完成时，在同一 Agent Loop 内提示继续；连续三次没有工具行动才暂停，不按整轮累计。复用持久化的 idleModelSteps，工具检查点或完成批次后重置；不使用后台定时重试。用户暂停、终止和真实请求错误优先于自动继续。切批消息明确上一批已完成、当前批待处理，完成全部批次后只生成总结，不再催促工具调用。

原生 Agent 在请求最终组装后的 `llm/stream` 边界计量实际消息（含任务和系统提示）及 JSON 工具定义，自动继续也走相同入口，仅用于诊断。单次输出长度沿用宿主/模型配置，插件不强制 32768 Token 上限，也不按 8192 Token 的普通文本长度提前中断。模型请求错误先交给宿主原生策略处理，包括上下文溢出后的摘要压缩与恢复；宿主拒绝恢复或耗尽其恢复预算后才持久化暂停。宿主摘要请求不被计作 Dreaming 工作步骤，不干扰本批的无工具进展计数；摘要自身用量由宿主记录。没有整轮时长或累计调用次数硬限额；完成后的总结请求也计量，但不重新激活任务或租约。

目录写入使用带必需 kind 的明确参数结构，操作数组必须扁平；错误不视为成功提交，Agent 可以纠正并重新提交。暂停时不为说明原因额外调用模型，而是在原生会话写入插件通知，报告真实原因、检查批次与已保存修改。start 每次创建新 run/session；resume 保留本轮会话与宿主保留的历史，并追加最新任务；之前版本已经裁掉的中间结论不能凭空恢复。

每批每次继续最多允许 64 次成功目录提交，达到后在当前步骤检查点暂停并保留已写入内容。用户明确继续或进入下一批时重新计数；页数与整轮调用量不受此上限限制。无工具循环在请求发送前被拦截时，不计入模型调用次数或 Token 消耗。

## 验证边界

测试使用隔离 SQLite 与 DSH JSONL 目录，验证真实 Agent Loop、工具拒绝、分批、写入、暂停/终止、用户补充、宿主重启恢复与完整会话。浏览器检查桌面/手机布局、浮窗原文、控制按钮与减少动画设置。测试模型是脚本化流，不证明真实模型能正确提炼经验；未改用户生产数据，也未发布。
