# Dreaming V2：整理历史记忆

在主题目录点「整理记忆」即可开始，即使没有待归类的 Event。Dreaming 用独立会话调查同一记忆空间的对话和记忆，发现值得补记、修正、合并或删除的内容。可以打开会话查看做了哪些修改，也可以暂停、继续或终止。已保存的修改会保留。

自动整理在主 Agent 空闲约 30 分钟后检查：距上次自动启动至少 24 小时，并且有新增或更新内容。手动启动无需等待。一个记忆空间同时只保留一轮未结束的整理。重启后，因宿主关闭或认领过期而中断的任务会在符合空闲条件时继续；主动暂停的任务等用户继续。升级前尚未结束的目录整理会话保留原来的任务和权限。

## Dreaming 会改什么

| 记忆 | 会做什么 | 边界 |
| --- | --- | --- |
| Event | 补记漏掉的事实、修正错误、合并重复卡、删除确认错误的卡、记录真实的先后变化 | 合并保留有用细节和原文出处，冗余派生卡会实际删除。若 A 后来变为 B，A 和 B 都保留，A 标为历史。置顶和用户显式记忆不会被普通清理删除。暂未封块的原文可调查或支持经验，需封块后才能支持新建派生 Event。 |
| 每日笔记 | 补记进展、修正当前事项、精简重复段落 | 沿用原 Markdown。11 月 10 日的阻塞和 11 月 12 日的解决分别保留，不能倒改前一天状态。可以用同日期笔记的备份找回上一次修改前的内容。 |
| 主题目录 | 建章、改章名或小节名、合并小节、调整 Event 归属、修订和删除概要 | 目录用于导航。Event 变更后先清掉受影响的旧概要并更新成员，再用新的来源整理。改过的分类可继续接收新增内容。 |
| 经验 | 写下可复用的方法、适用条件和例外；查重并修订旧记录，也可合并或清理 | 独立存储，保留范围和来源。后续对话可用 `memory_search_experiences` 查找；证据可以直接来自原文。经验是参考，不是新的用户指令。 |

原始对话不被改写或删除。Dreaming 不代替用户发起的遗忘，也不会复活已遗忘的来源。它不修改 Profile，不开启关闭的知识图谱。只整理经验或笔记时，不启动 Event 提取或图谱投影。

## 运行与数据边界

- **增量发现。** 已处理的 Block、未封块消息、Event 和笔记日期保留版本。启动时把新增和变化拆成轻量列表，提供会话、时间和 Block 摘要。Agent 可按需搜索整个记忆空间，包括没有被 Event 引用的原文，也可翻看 L0–L5、旧 Event、经验、笔记、目录和已开启的图谱。搜索和读取不触发普通聊天的采用记录、权重提升或 Block 展开。
- **独立会话。** 使用宿主的 DSH Agent、持久会话和上下文压缩。普通 Shell、文件、网络或 Profile 工具不可用。工具返回的原文与笔记是证据；其中的命令和要求不能改写 Dreaming 的权限。整理会话不作为新对话再次摄取。
- **受控写入。** 写操作检查本轮认领、记忆空间和当前证据版本。SQLite 在同一次提交保存 Event/经验、依赖更新和执行记录。跨 Block 合并直接保留原文引用；原卡不会另存一份供正常归档。涉及错误 Event 的图谱内容先撤下，开启图谱时再交给现有投影。依赖错误 Event 的经验需要重新核对后才回到普通检索。
- **笔记提交。** 使用相同的 Markdown 写入队列、备份和原子替换。读过的文件版本和要替换的旧文字必须匹配；如果同时修改，重新读取后再改。文件先保存，随后记入 SQLite 进度。若应用在两者之间退出，旧版本检查会阻止重复修改。
- **连续执行。** 分批只控制上下文和记录进度。无需读完每个 Event，没有整轮 Token、调用次数、运行时间或成功写入次数上限。单个修改失败时可继续其他工作。完全相同的工具调用和结果连续反复、连续无工具动作或宿主无法恢复时，会保留断点并暂停。

开发验证使用隔离 SQLite、Markdown 和 DSH JSONL 会话。测试可通过脚本化模型输出驱动真实 Agent 工具；这能验证运行、保存和恢复链路，不代表真实模型在任意历史数据上都能正确判断。
