# 大库数据访问与增量保存

这轮改动沿用 SQLite 的事务、索引和版本检查。日常列表使用独立读模型，常用小修改直接提交局部记录；涉及派生关系的操作通过工作单元提交变化的记录。没有新增数据库引擎、ORM 或 schema 迁移。

## 读取

- `SqliteStorage.readBlockPage` 在同一只读事务里读取导航元数据，按会话、顺序和分页选出块，再补齐当前页的原文与工具载荷。轮次、总数、衰减位置继续基于完整导航数据计算。
- `readDashboardEntries` 为首页读取元数据，只补齐当前块页与当前审计页实际需要返回的原文。事件列表通过 `readEventModel` 读取元数据，筛选和分页后再加工展示字段。
- `AdminReadModel` 没有 `schemaVersion`，因此不能误传给需要完整快照的保存接口。它不用于原文详情、导出或助手证据读取。
- 块、事件、任务、节点及元素之间的关联在一次请求内建立索引，保持原来的顺序、去重规则和虚拟分块范围。
- 旧 schema 和混合会话的块列表保留完整恢复路径。块搜索仍按完整返回对象匹配，再分页，保留已有搜索语义。
- dashboard 条件请求先读取空间版本、设置及去重维护状态。ETag 相同直接返回 304，不读取页面原文；分页、搜索和事件筛选条件属于缓存键。

## 写入与内存一致性

`StorageAdapter.commitRecords` 是可选能力，提供追加对话、块指针、事件置顶和采用回执几个业务事务。事务检查预期版本；成功后同步更新内存和版本，失败不发布这次内存变化。重复采用回执在修改队列内再次检查，避免同时到达的请求重复强化。

`saveChanges` 为其他派生、导入和语义修改提供工作单元：比较记录元数据、原文位置及明确的原文修改，只写变化的行，删除失效来源关系，原文和全文索引在同一个事务中处理。原有 `save` 入口及不支持新能力的适配器继续可用。

版本检查不能替代任务租约检查。图谱撤权、任务身份、并发心跳合并和事务失败回滚沿用原机制；计算变化集合发生在合并当前租约之后。

旧接口允许调用者修改返回的事件、块或原文文本，再由后续操作保存。为兼容这种用法，引擎保留已提交的记录元数据基线；检测到未提交修改时，常用小操作转入工作单元，一并保存相关变化。`getBlockContext` 产生的派生指针变化可合并进入同一层级事务。

工具载荷由引擎持有独立的 JSON 值，首次接入持久化状态时冻结，后续保存共享这些不可变值，避免反复深拷贝全部历史工具结果。调用方传入的对象不被冻结；完整导出仍返回可以独立编辑的副本。原文文本和工具载荷整体替换可以由记录差异识别；不应原地修改已存储工具载荷的内部字段。

## 验证与边界

新增测试比较完整保存与增量保存的重开结果，检查实际 SQL 更新范围，注入事务中途失败，覆盖重复回执、过期写入、输入对象所有权和旧对象修改。API 测试比较新旧列表及 dashboard 的完整 JSON，包含跨页搜索、旧会话、空页、超过 40 块的后续页、审计来源和条件请求。

基准使用 24 / 96 / 384 块隔离构造库，每块四轮对话及工具 JSON。旧实现来自本次修改前保存的工作区源码；每项热操作保留 9 个原始样本，冷首次请求单列。原始记录见 `.benchmarks/database-access/results.json`；源码基线和原有工作区差异保存在 `.artifacts/database-access-before/`。测量不包含模型、向量服务或真实用户数据库，不能据此推算真实 DSH 的整轮响应时间。

剩余成本包括：导航和关联元数据的扫描、完整语义搜索、旧数据恢复、变化的图谱/主题 JSON 文档及复杂派生操作的元数据比较。助手运行时仍会缓存已打开空间；这次没有移除所有完整快照入口，也没有把所有复杂写入改成专用 SQL 命令。schema 保持 14，并以修改前的 SQLite 读取器核对新事务产物的可读性。
